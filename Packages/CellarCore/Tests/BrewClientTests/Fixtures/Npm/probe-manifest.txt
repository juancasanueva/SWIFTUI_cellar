Redaction
---------
Every captured byte is verbatim except the home directory component of absolute
paths, which was rewritten from the capturing machine's `/Users/<user>/` to
`/Users/example/`. Nothing else was edited: no key was added, removed, reordered
or reformatted. The substitution keeps a committed fixture from pinning one
developer's home directory while preserving the exact document shape the decoder
must read.

Deviation from the read-only command list
-----------------------------------------
The task allowed `--version`, `ls -g --json --depth=0`, `outdated -g --json` and
`prefix -g`. `install-g.stdout` was captured with a fifth invocation:
`npm install -g --dry-run --prefix <session scratch directory> left-pad@1.3.0`.
`--dry-run` writes nothing, and `--prefix` pointed at a throwaway directory
inside the session scratchpad, so the machine's global packages were neither
read from nor written to. The directory listing after the run was empty,
confirming no file was created. Recorded here rather than silently taken.

Hand-authored fixtures
----------------------
These could not be produced on this machine without corrupting the real global
prefix or a system-owned directory. Each is written to npm 11's exact error
format, which the real `outdated-g-offline.stderr` capture above establishes
(`npm error code <CODE>` first, `npm error A complete log ...` last).

| Fixture | Why it is hand-authored |
|---|---|
| ls-g-problems.stdout / ls-g-problems.stderr (exit 1) | `ELSPROBLEMS` needs a global package with an unsatisfied dependency. Two read-only attempts were made in a scratch prefix — a broken `package.json` beside the installed package, then a root manifest naming a missing and an out-of-range dependency — and npm 11 reported neither at `--depth=0`, exiting 0 both times. Producing it for real would mean breaking the machine's actual global prefix. The document keeps the shape the real `ls` capture shows and adds the `problems` array npm emits alongside it. |
| install-g-eacces.stderr | Requires a prefix the user cannot write to, i.e. an attempted write into a root-owned directory. Modelled on npm 11's `EACCES` output for `/usr/local/lib/node_modules`. |
| uninstall-g.stdout | The real removal line needs a package actually installed and then removed. A dry-run uninstall against an empty scratch prefix printed `up to date`, which is the wrong shape to fixture. Written as npm 11's `removed 1 package in <n>ms`. |

Consumers
---------
`ls-g-*` and `outdated-g-*` back the unit 1 decoder and payload tests.
`install-g*` and `uninstall-g.stdout` back the unit 2 outcome classification
tests; nothing in unit 1 reads them.
